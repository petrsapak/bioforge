# Session 2026-11-03: Bioforge Lab (New game did nothing in the desktop build)

## New game shows the main menu again (user: "I just clicked new game and the game does nothing it shows main menu again")
- Cause: switching games reloads the page (`restartIntoGame` in `bioforge-lab/menus.js` sets
  `bioforge-lab-start-with`, then calls `location.reload()`). In Electron 45, `location.reload()` fires
  `will-navigate`, and `lockToGamePage` in `desktop/main.js` cancelled every `will-navigate`, so the reload never
  happened. The screen faded out and came back to the same menu. New game with a played game, Load game, deleting
  the current game and Continue after a Sandbox all go through this reload.
- The browser build was not affected: headless Edge over the DevTools protocol showed New game after a reload making
  game 2 and starting it.
- Fix: `will-navigate` now lets the page navigate to its own URL (a reload) and still blocks everything else.
- Checked with a small Electron probe (in the scratchpad, not the repo): before the fix, `will-navigate` fired and
  the page loaded once. After it, the page loaded twice, and the second load saw the `start-with` value. The page had
  sent about 500 KB of `saves:set` messages just before the reload; 3 runs out of 3.

## Done
- `desktop/main.js`: `lockToGamePage` allows reloading the game page.
- Version 0.7.23 (`data/version.js`, `desktop/package.json`, `CHANGELOG.md`).

## Launch opened at level 1 with the Levels sheet (user: "this is the first screen I see ... wtf is this?")
- After the fix, `npm run desktop` opened on game 5, with level 1 chosen and the Levels sheet open. This is the
  screen New game is meant to show. The save file had games 3, 4 and 5; games 4 and 5 have no level results.
  Games 3 and 4 were made by New game clicks whose reload was blocked (game 4 at 15:20).
- Likely cause: a blocked reload left `bioforge-lab-start-with` = `'new-game'` in the save file. The next launch
  read it and started a new game instead of showing the main menu. Game 5's last-played time (15:34:02, version
  0.7.23) fits this, and also fits a New game click on this launch, so it is not certain.
- Fix: `createGameWindow` in `desktop/main.js` clears `bioforge-lab-start-with` before the page loads. A launch now
  always opens the main menu, and only the game's own reload uses the flag.

## New game starts with a 7-cell creature (user: "why the fuck is this the creature when I click New Game")
- Cause: the Lab always starts with the Jet template in the builder (`START_DESIGN = 'jet'` in
  `bioforge-lab/ui.js`, since 2026-10-28), and `beginNewGame` in `bioforge-lab/menus.js` never replaced it. The Jet
  already solves level 1 (its hint describes the Jet), and its Mouth, Gill, Heart and Pore aren't open at level 1.
  This was not the blocked reload: a test showed the new game's creature was the Jet, not the last game's creature.
- Fix: `beginNewGame` loads `bareDesign()` (just the Nucleus), as the Sandbox already did.
- New check in `tests/menus.js`: the new game's saved and shown creature is one cell, while the game before had more.
- Headless Edge (DevTools protocol): New game on a fresh game and New game after a reload both saved a 1-cell design.

## Deleting a game goes back to the main menu (user: "when I click to delete saved game then it should delete it and stay in the same screen")
- Cause: deleting the current game reloads the page so that another game becomes current. `deleteGameAsked` in
  `bioforge-lab/gamesview.js` passed no `start-with`, so the reload opened the bare main menu. Deleting another game
  already stayed on the screen, with no reload.
- Fix: it passes `'load-game'`, and `setUpMenus` in `bioforge-lab/menus.js` then opens the Load game screen over the
  main menu.
- New checks in `tests/menus.js`: deleting the current game reloads with `'load-game'`, and after the reload the Load
  game screen is open over the main menu.
- Headless Edge: after New game, a reload, Load game, ✕ on the current game and Delete, the page reloaded with the
  Load game screen open and game 1 gone.
