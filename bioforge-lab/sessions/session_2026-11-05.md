## Nerve lanes (user: "why is it not centered the nerve endings")
- The user asked to brainstorm the nerves: "just one nerve line per cell", where every cell a line passes through
  takes its signal. Talked through, not built: lines on one hex grid can't cross, so the crossed Seeker (level 2)
  would need a crossing cell; a neuron could take only one line, so the Synapse's AND could not be wired; and every
  level, save and tutorial line would change. User: "ok so that doesn't work ... Let's not go in that direction".
- Ten options for laying and showing fibres were shown on a page (colour by source, one branching nerve per
  source, cables with a count, clear centres, arcs, letters, focus on one cell, pulses, a wiring table, pulling the
  route). User: "I think that can stay as it is now", and asked to see fibres running along each other in detail.
- A second page drew six cases with the game's own scripts. Cause of the off-centre look: each fibre had one lane
  for its whole length, given out from the centre outward (0, +1, −1, +2…), so the first fibre kept the centre line
  and the rest, ends included, sat to one side.
- The user's rule: "One line from cell A to cell B, will go from the edge of the cell in one of the 6 directions
  (because it is hex) perpendiculary and in the middle. When I add another one the it will line up next to the first
  one and it will move the first one off the center". Built and approved ("ok go with this"):
  - `fibres.js`: `layOutFibreLanes` now places fibres per cell side. A fibre crosses each side square to it; the
    fibres on one side are spread evenly round its middle, `FIBRE_LANE_GAP` (2.2 px) apart, squeezed into
    `FIBRE_SIDE_SPREAD` (9 px) when more than 5 cross it. Inside a cell a fibre bends (a curve, `FIBRE_BEND_PULL`)
    from the side it comes in by to the side it leaves by, and its ends run square to their side to
    `LINK_END_GAP` short of the cell's middle. Fibres on one side are ordered by where their routes part, followed
    both ways, so fibres running together keep one order and don't cross. It returns `{ line, colorIndex }`; the
    old `lane` number and the per-fibre offset line (`offsetPolyline`) are gone.
  - `render.js`: `drawFibre` takes the finished line; `builder.js` (picking a fibre) and `builderview.js` use it.
    A fibre being dragged is still drawn through the cells' centres (`smoothLinkLine`).
- Chosen without asking: version 0.7.30, since 0.7.29 was tagged. Drawing only; the sim and the golden tests are
  untouched.

## Desktop crash on saving (user: screenshot of "Uncaught Exception: Error: EPERM: operation not permitted, rename '…save.json.tmp' -> '…save.json'")
- Cause: `desktop/saves.js` writes `save.json.tmp` and renames it over `save.json`. On Windows the rename fails
  with EPERM while another program (Defender, the search indexer, OneDrive) has the save open for a moment. The
  error was not caught, so it reached Electron's main process as an uncaught exception and its error box.
- Fix in `desktop/saves.js`: `renameWithRetries` tries the rename 5 times, 30 ms apart; a write that still fails is
  logged and tried again after 2 s, with the changes kept in memory; the flush on quitting never throws.
- `desktop/tests/saves.js`: a rename refused twice goes in; one refused every time doesn't crash and is written
  once the file is free; flushing on quit with the file held doesn't throw. Against the old `saves.js` the test
  dies with the same uncaught EPERM.
